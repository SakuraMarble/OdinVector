# 3月23日汇报-混合检索的迁移与动态混合检索的实现

## 基于OdinANN的混合检索实现

### 实现思路

基于hit_rate选择搜索方案

* 【<hit_rate】基于IVF标签索引和PQ量化的两阶段暴力搜索

* 【>hit_rate】基于Vamana图索引搜索，沿途**收集**符合标签约束的节点

### 基于IVF标签索引和PQ量化的两阶段暴力搜索

* 首先通过IVF标签索引，快速获取满足标签约束的向量ID集合condidate_set

  ```cpp
  roaring::Roaring candidates = parser.parse(query_labels[i]);
  ```

* 根据内存中驻留的PQ压缩向量大小对candidate_set中的向量进行排序，取top(L*multiplier)小的向量，其中multiplier为可以设置的参数

  ```cpp
  // --- Stage 1: PQ coarse ranking ---
      std::vector<float> pq_dist_results;
      compute_pq_dists_batch<T>(index, query, candidate_ids, pq_dist_results);
  
      size_t num_candidates = candidate_ids.size();
      std::vector<SearchResult> pq_results(num_candidates);
      for (size_t i = 0; i < num_candidates; ++i) {
          pq_results[i] = {candidate_ids[i], pq_dist_results[i]};
      }
  
      size_t actual_L = std::min((size_t)top_L, pq_results.size());
      if (actual_L < pq_results.size()) {
          std::nth_element(pq_results.begin(),
                           pq_results.begin() + actual_L,
                           pq_results.end());
      }
      std::sort(pq_results.begin(), pq_results.begin() + actual_L);
  ```

* 再对这个小集合中的向量进行IO，获取精确的向量信息，进行精确重排序

  ```cpp
  // --- Stage 2: Exact rerank via mmap ---
      std::vector<SearchResult> rerank_results(actual_L);
  
      if constexpr (std::is_same<T, uint8_t>::value) {
          const uint8_t* query_u8 = reinterpret_cast<const uint8_t*>(query);
          for (size_t i = 0; i < actual_L; ++i) {
              uint32_t vid = pq_results[i].id;
              const T* raw_ptr = raw_reader.get_vec(vid);
              if (raw_ptr) {
                  float d = L2_AVX2_Uint8(query_u8,
                                          reinterpret_cast<const uint8_t*>(raw_ptr),
                                          query_dim);
                  rerank_results[i] = {vid, d};
              } else {
                  rerank_results[i] = {vid, std::numeric_limits<float>::max()};
              }
          }
      } else if constexpr (std::is_same<T, float>::value) {
          ...
          }
      } else {
          // int8 and other types: convert to float
          ...
      }
  ```

* 最后返回topK

  ```cpp
   // --- Stage 3: Select final top-K ---
      size_t actual_K = std::min((size_t)final_K, rerank_results.size());
      if (actual_K < rerank_results.size()) {
          std::nth_element(rerank_results.begin(),
                           rerank_results.begin() + actual_K,
                           rerank_results.end());
      }
      std::sort(rerank_results.begin(), rerank_results.begin() + actual_K);
  
      result_ids.resize(final_K);
      result_dists.resize(final_K);
      for (size_t i = 0; i < actual_K; ++i) {
          result_ids[i] = rerank_results[i].id;
          result_dists[i] = rerank_results[i].dist;
      }
      for (size_t i = actual_K; i < final_K; ++i) {
          result_ids[i] = 0;
          result_dists[i] = std::numeric_limits<float>::max();
      }
  ```

### 基于Vamana图索引搜索，沿途收集符合标签的节点

#### 核心背景与挑战

在 SSD 向量索引中，完整的高维向量存储在磁盘上，而内存中只保留压缩后的向量（通常使用 PQ 量化，比如 128 维压成 64 维）。

- **痛点 1（过滤饥饿）**：如果只顺着图的连通性找，满足标签的节点可能非常稀疏，导致搜索路径被大量不满足标签的节点带偏，真正的目标节点根本没机会被访问。
- **痛点 2（PQ 误差）**：如果仅仅使用 PQ 压缩距离来决定最终的 Top-K，由于压缩带来的精度损失，真正的最近邻节点可能会因为 PQ 距离被高估而被错误丢弃。
- **痛点 3（IO 瓶颈）**：每次读磁盘获取精确向量的开销极大，不能遇到一个符合标签的节点就去读一次盘。

为了完美平衡**精度、召回率和 IO 性能**，进行如下新的数据结构设计：

* 最终结果池 `exact_result_heap`（这是一个维护精确距离的 Top-K 堆）
* 是否已计算精确距离标记`exact_computed_set`，避免重复IO与计算。
* 海选池`pq_candidate_heap`（容量设置为`refine_capacity`，比较大，专门用于吸收PQ距离的误差，防止潜在的好的向量被漏掉）

#### 第一阶段：图遍历与海选

1. **全局导航入场**： 搜索从全局的中心点（`best_medoid`）开始。即使中心点不满足标签也没关系，它的作用只是作为“高速公路”的入口，快速引向距离 Query 最近的宏观空间。

2. **提取前沿节点（Frontier）并读取磁盘**： 每一轮迭代，从候选队列 `retset` 中拿出几个（`beam_width`）最有希望的节点，向 SSD 发起一次并发读取（`reader->read`），把这些节点所在的 4KB 数据块（包含它们自己的完整向量和它们的邻居列表）读进内存。

3. **“免费 IO”**： 由于包含该节点精确向量的 4KB 数据块已经被读入内存，此时计算它的精确距离是**零额外 IO 成本**的。 代码会立刻计算它的精确距离 `cur_expanded_dist`，如果它满足标签，直接把它放入**最终结果池 `exact_result_heap`**，并标记为已计算（`exact_computed_set`）。

   ```cpp
   for (auto &frontier_nhood : frontier_nhoods) {
       auto [id, loc, sector_buf] = frontier_nhood;
       char *node_disk_buf = offset_to_loc(sector_buf, loc);
       unsigned *node_buf = offset_to_node_nhood(node_disk_buf);
       _u64 nnbrs = (_u64) (*node_buf);
       T *node_fp_coords = offset_to_node_coords(node_disk_buf);
       assert(data_buf_idx < MAX_N_CMPS);
   
       T *node_fp_coords_copy = data_buf + (data_buf_idx * aligned_dim);
       data_buf_idx++;
       memcpy(node_fp_coords_copy, node_fp_coords, data_dim * sizeof(T));
       float cur_expanded_dist = dist_cmp->compare(query, node_fp_coords_copy, (unsigned) aligned_dim);
   
       if (coord_map != nullptr) {
         coord_map->insert(std::make_pair(id, node_fp_coords_copy));
       }
   
       // 在此处收集精确结果，并且打上 "已计算" 的标记
       exact_computed_set.insert(id);
       uint32_t tag = id2tag(id);
       if (candidate_set->find(tag) != candidate_set->end()) {
           push_to_heap(exact_result_heap, Neighbor(id, cur_expanded_dist, true), k_search);
       }
       ...
   }
   ```

4. **遍历邻居与 PQ 海选（宽进策略）**： 对于刚才读出来的邻居列表，使用内存中极快的 PQ 距离进行批量计算（`compute_dists`）。

   - **更新路径**：将这些邻居中满足加入要求的向量加入 `retset`，继续引导后续的搜索方向。（这里保持不变）

     ```cpp
     if (dist >= retset[cur_list_size - 1].distance && (cur_list_size == l_search))
         continue;
               
     Neighbor nn(nbr_id, dist, true);
     auto r = InsertIntoPool(retset.data(), cur_list_size, nn);
     
     if (cur_list_size < l_search) {
         ++cur_list_size;
         if (unlikely(cur_list_size >= retset.size())) {
           retset.resize(2 * cur_list_size);
         }
     }
     if (r < nk) nk = r;
     ```

   - **海选池兜底**：如果某个邻居**满足标签**，不管它有没有被选入主搜索路径，都将它加入一个容量极大的海选池 `pq_candidate_heap`。

     ```cpp
     for (_u64 m = 0; m < nnbrs; ++m) {
       unsigned nbr_id = node_nbrs[m];
       if (unlikely(nbr_id > this->cur_id)) {
         LOG(ERROR) << "ID is larger than current ID, " << nbr_id << " vs " << this->cur_id;
         crash();
       }
       if (visited.find(nbr_id) != visited.end()) continue;
     
       visited.insert(nbr_id);
       cmps++;
       float dist = dist_scratch[m];
       if (stats != nullptr) stats->n_cmps++;
     
       // 这里只使用 PQ 距离收集候选集，不干扰精确对比池
       uint32_t nbr_tag = id2tag(nbr_id);
       if (candidate_set->find(nbr_tag) != candidate_set->end()) {
           push_to_heap(pq_candidate_heap, Neighbor(nbr_id, dist, true), refine_capacity);
       }
     
       if (dist >= retset[cur_list_size - 1].distance && (cur_list_size == l_search))
         continue;
       ...
     }
     ```

5. 动态更新L，如果`retset`中符合要求的标签太少了，就增大探测范围。

   ```cpp
   if (dyn_search_l) {
     _u32 tot = 0, cur = 0;
     for (cur = 0; cur < cur_list_size; ++cur) {
       uint32_t tag_dyn = id2tag(retset[cur].id);
       if (exclude_nodes->find(tag_dyn) == exclude_nodes->end() && candidate_set->find(tag_dyn) != candidate_set->end()) { // 动态调整时也要考虑过滤条件，尽可能增大探测范围
         ++tot;
         if (tot == original_l_search) break;
       }
     }
     l_search = std::max(original_l_search, cur + 1);
   }
   ```

#### 第二阶段：兜底重排与终面

当图搜索因为到达步数或时间限制而停止时，触发此阶段。

1. **清点海选池**： 图遍历结束后，海选池 `pq_candidate_heap` 里装满了成百上千个“满足标签、且 PQ 距离看起来不错”的潜力节点。但它们当中有很多向量在第一阶段并没有机会被深入展开（即没有触发过 IO，不知道真实距离）。

2. **剔除已经历精确距离计算的向量**： 遍历海选池，利用 `exact_computed_set` 过滤掉那些在第一阶段已经蹭到“免费 IO”并计算过精确距离的节点。剩下的就是需要“终面”的 `refine_ids`。

   ```cpp
   std::vector<uint32_t> refine_ids;
   while (!pq_candidate_heap.empty()) {
       uint32_t cid = pq_candidate_heap.top().id;
       pq_candidate_heap.pop();
       // 只有没被免费 IO 过精确坐标的节点，才进入这一步
       if (exact_computed_set.find(cid) == exact_computed_set.end()) {
           refine_ids.push_back(cid);
           exact_computed_set.insert(cid); // 防止在 Batch 中重复
       }
   }
   ```

3. **统一 Batch IO**： 将这些没验过精确距离的节点，按批次组装成 IO 请求（`frontier_read_reqs`），向 SSD 发起统一的 Batch 读取。 拿到它们真正的完整向量后，计算精确距离，并将其投入最终的 `exact_result_heap` 中进行最后一次 Top-K 筛选。

   ```cpp
   // 分批次读取，防止超出 sector_scratch 容量（每次读取量设定为 beam_width）
   size_t processed = 0;
   while (processed < refine_ids.size()) {
       size_t batch_size = std::min((size_t)beam_width, refine_ids.size() - processed);
       std::vector<uint32_t> batch_ids(refine_ids.begin() + processed, refine_ids.begin() + processed + batch_size);
       ...
       for (size_t i = 0; i < batch_ids.size(); i++) {
           ...
       }
   
       io_timer.reset();
   #ifdef DIRECT_READ_CC
       reader->read(frontier_read_reqs, ctx);
   #else
       reader->read_alloc(frontier_read_reqs, ctx, &page_ref);
   #endif
       if (stats != nullptr) stats->io_us += (double) io_timer.elapsed();
       this->unlock_idx(idx_lock_table, locked);
   
       cpu_timer.reset();
       for (auto &frontier_nhood : frontier_nhoods) {
           ...
           // 使用精确距离纳入最终结果池
           push_to_heap(exact_result_heap, Neighbor(id, exact_dist, true), k_search);
       }
       ...
   }
   ```

#### 第三阶段：整理输出

最后，将 `exact_result_heap` 中经过精确距离比拼胜出的前 K 个节点弹出，翻转顺序（因为大顶堆弹出的是逆序的），存入 `full_retset` 返回给上层。

#### 总结与分析

1. **解决了过滤饥饿痛点**：只要在图遍历中“远远看了一眼”符合标签的邻居，它就会被抓进 `pq_candidate_heap`，绝不会因为 PQ 距离的微弱劣势而彻底丢失。并且，在执行Vamana图搜索过程中是逐渐接近目标向量的，但是如果只收集“主干道”的向量会因为满足标签的向量仍不够多而错失本应召回的向量。因此，不仅将“主干道”上的节点（即符合标签约束，且PQ距离在一众邻居中胜出，即将展开的节点）放入结果集，也将PQ距离没那么好但是符合标签的向量放入海选集，大大拓宽了搜索视野。

2. **100% 精确度**：最终返回的结果，**全部都是经过精确距离校验的**，彻底消除了 PQ 降维带来的距离扭曲。

3. **高效的 IO 优化**：核心搜索路径上的精确校验是蹭了图遍历所需 IO 的“免费车”；而对候选池的校验被推迟到了搜索最后，通过一次性的 Batch IO 解决，避免了在 `while` 循环内部发生频繁的同步 IO 阻塞，对 NVMe SSD 的高并发队列极其友好。

## 动态混合检索实现

最native的思路为用追加`.txt`文件的方式来记录新向量的标签，积攒一定数目后重新构建ivf索引。这个思路的来源是：原本向量标签就是这样生成ivf.index的，而磁盘上的ivf.index本身为紧密排列，难以动态维护（就地插入/删除面临着大规模移动），于是尝试动态维护向量id->tags的文本文件。

追加`.txt`文件的方式面临两大问题：

1. **读放大极其严重**：每次查询都要遍历文本文件，随着新插入的向量增多，查询延迟会呈线性爆炸（从 $O(1)$ 退化为 $O(N)$）。
2. **写放大极其严重**：Merge 时要排除删除的 ID 并把所有数据重新过一遍，等于每次 Merge 都在做全量重构（Full Rebuild），耗时极长，系统会卡死。

新思路为**LSM-Tree（Log-Structured Merge-Tree）思想的“双层倒排索引”架构**。摒弃遍历文本文件的做法，在内存中维护一个轻量级的“动态倒排索引（MemTable）”，并在查询时与磁盘索引（SSTable）进行位运算合并。

### 核心架构：双层倒排索引 + 墓碑机制

把倒排索引拆分成三个组件：

1. **Disk Index（磁盘只读索引）**：也就是目前已经写好的、序列化到磁盘的那个不可变的 Roaring Bitmap 集合。
2. **Mem Index（内存动态索引）**：一个纯粹在内存里的 `std::unordered_map<int, roaring::Roaring>`，专门用来接收新插入的标签。
3. **Deleted Bitmap（全局墓碑/删除位图）**：一个全局的 Roaring Bitmap，记录所有被删除的内部 ID (`vid`)。

------

### 工作流重构

#### 1. 动态插入 (Insert)

当一个新向量（`vid = 100001`，`labels = [A, B]`）进来时：

- 更新图索引（分配 `vid`）。
- **更新 Mem Index**：直接在内存里执行 `MemIndex[A].add(100001)` 和 `MemIndex[B].add(100001)`。
- 为了防止宕机丢失数据，可以把这行操作追加到一个二进制的 WAL (Write-Ahead Log) 文件中，**但这个文件只用于重启恢复，绝不用于实时查询**。

#### 2. 动态删除 (Delete)

当要删除 `vid = 500` 时：

- 不需要去 Disk Index 或 Mem Index 里吭哧吭哧找它并删除它。
- **直接打墓碑**：执行 `DeletedBitmap.add(500)`。这是 $O(1)$ 的操作。

#### 3. 实时查询 (Query) 

这是双层架构最巧妙的地方。当需要查询标签 `A` 和 `B` 的交集时，只需要做简单的 Bitmap 逻辑运算，完全不需要遍历任何实体数据：

```cpp
// 1. 获取包含 A 的完整位图：磁盘的 A并上内存的 A
Roaring bitmap_A = DiskIndex[A] | MemIndex[A];

// 2. 获取包含 B 的完整位图：磁盘的 B并上内存的 B
Roaring bitmap_B = DiskIndex[B] | MemIndex[B];

// 3. 求交集
Roaring result = bitmap_A & bitmap_B;

// 4. 剔除所有已删除的向量
result -= DeletedBitmap;

return result; // 完美！这就是最终合法的 candidate_ids
```

*Roaring Bitmap 的位运算经过了极致的 SIMD 优化，即使是千万级别的数据，上述 `|`、`&`、`-` 运算的耗时也仅在亚毫秒级（< 1ms）。*

#### 4. 异步合并 (Merge / Compaction)

在 Merge 时，**完全不需要重新解析原始数据或重新构造索引**。

因为底层都是 Roaring Bitmap，Merge 过程纯粹是对 Bitmap 进行数学合并，速度极快：

- 后台线程启动 Merge：

- 遍历目前存在的所有标签：

  `New_DiskIndex[Tag] = (Old_DiskIndex[Tag] | MemIndex[Tag]) - DeletedBitmap;`

- 将 `New_DiskIndex` 按照之前的格式重新序列化到磁盘。

- 清空当前的 `MemIndex` 和 `DeletedBitmap`。

- 清理当前的WAL文件。

#### 5. 故障恢复 (Recovery)

当系统重新启动并调用 `recover_from_wal` 时，它会遵循以下逻辑：

1. **加载基准快照**：首先通过 `load()` 加载最近一次 `merge` 后的磁盘索引（`_disk_index`）。此时内存层是空的。
2. **定位日志起点**：打开 WAL 文件。由于在 `merge` 完成后会使用 `std::ios::trunc` 清空 WAL，因此恢复程序只需要**从头到尾顺序扫描**当前的 WAL 文件即可。
3. **重放（Replay）操作**：
   - 读取一个操作类型标记（`INSERT` 或 `REMOVE`）。
   - 如果是 `INSERT`：读取 `vid` 和 `tags`，调用 `_apply_insert_to_mem`。这会自动更新内存中的位图，并将该 `vid` 从 `_deleted_bitmap` 中移除。
   - 如果是 `REMOVE`：读取 `vid`，调用 `_apply_remove_to_mem`。这会将 `vid` 加入到墓碑位图。
4. **状态重建**：扫描完成后，内存中的 `_mem_index` 和 `_deleted_bitmap` 将精确恢复到崩溃前的状态。
