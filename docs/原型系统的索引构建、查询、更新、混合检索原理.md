# 原型系统的索引构建、查询、更新、混合检索原理

## 构建

构建过程首先进行数据预处理与 PQ 训练，对原始高维向量进行针对内积距离的归一化处理，并从数据集中随机采样进行 K-means 聚类以训练乘积量化码本，进而利用该码本将所有原始浮点向量压缩为紧凑的 PQ 编码，加速后续距离计算。

随后进入内存 Vamana 图构建阶段，采用贪婪搜索策略为每个节点寻找候选邻居，并利用 Alpha 剪枝机制控制图的度数 R，以保证图的稀疏性与连通性，这一阶段通常需要将图结构和向量数据完整加载至内存，是构建过程中的内存峰值点。

在完成图构建后，系统会将内存图结构转化为磁盘友好的布局，通过将邻接表与向量数据合并并按照 4KB 扇区进行对齐，以减少搜索时的 I/O 读取放大；若数据量达到十亿级等超大规模，则会采用基于分片的构建策略。

最后，系统会生成用于加速搜索起点的内存索引，并初始化 ID-to-Location 映射表和标签映射表，为后续的动态搜索与更新做好准备。

## 搜索

OdinANN 的搜索流程采用了“内存缓存导航 + 磁盘图遍历”的两级架构，并针对动态环境引入了 ID 转换与有效性过滤机制。

查询请求首先在常驻内存的采样图中进行贪婪搜索，快速定位到距离查询向量较近的一个或多个候选节点，作为磁盘搜索的入口点。

进入磁盘搜索阶段后，系统不再直接使用 ID 进行磁盘寻址，而是先查询 ID-to-Location 映射表以获取其最新的物理扇区地址。值得注意的是，在扩展邻居节点时，系统会引入逻辑删除过滤机制，实时检查内存中的已删除 ID 集合。若遇到已标记为删除的节点，OdinANN 不会立即终止路径，而是将其作为“跳板”继续路由，但在最终生成结果集时会将其剔除，并动态扩展搜索列表长度 L以补偿召回率损失。

最后，根据获取的物理地址，系统通过异步 I/O 读取对应的磁盘页，利用预计算的 PQ 距离表快速筛选候选邻居，并对高优候选者读取原始向量进行精确距离重排，直至搜索收敛。

## 更新

OdinANN 的更新流程涵盖插入、修改与删除，其核心在于利用“读-改-写”（RMW）机制和页面分配规则实现高效的直接插入。

在插入新向量时，系统依据三条优先级规则寻找物理写入位置：优先复用全空页面，其次复用搜索路径上已缓存且有空位的页面，若无空位则在文件末尾分配新页。

确定位置后，系统锁定相关页面，读取邻居节点的邻接表并在内存中更新连接关系，最后将修改后的数据原子性地写回磁盘，该过程不依赖 WAL 日志即可实现持久化，写入成功后会立即更新内存中的 ID-to-Location 映射。

对于删除和更新操作，OdinANN 采用逻辑删除与异地更新策略。删除操作采用懒惰策略，仅将 ID 加入内存的已删除集合，不立即执行物理数据搬移；

更新操作则实现为“逻辑删除旧版本 + 插入新版本”，旧 ID 被标记删除，新数据作为新 ID 写入新的物理位置，从而避免了原地修改带来的数据覆盖风险。

当删除节点的比例或 I/O 放大系数超过阈值时，系统会触发后台垃圾回收任务，扫描磁盘并物理移除被标记删除的节点，同时对受影响的邻居进行“桥接”修复，将指向死节点的连边替换为其有效邻居，从而回收磁盘空间并优化索引结构。
